# Plan — WEB-037

- Context:
  WEB-020 and WEB-021 were superseded on 2026-07-26: their partial UAT evidence
  targeted the pre-redesign production build, and the WEB-035/036 merges have since
  reached `www.finspeed.online` through the Amplify main-branch release path. The
  live build has never had a production UAT pass: the redesigned storefront, the
  seven-stage configurator with the exhaustive visual matrix and the stock-poster
  catalog correction, the distributor access gate, and the fail-closed consent
  system are all in production on local evidence alone. This slice runs the
  successor UAT directly against production per
  `specs/references/handoff/_shared/tests/uat-ux-aesthetics.md`.
- Goals:
  - Execute a scripted, reproducible UAT sweep of production covering home, shop,
    product detail, the configurator (stock and custom paths), cart/checkout,
    search, dealers, distributor gate, support, brand story, testimonials, and
    blog, at desktop and mobile widths in both themes.
  - Verify in production that the distributor gate redirects unauthenticated
    portal paths and that analytics fails closed (no events before a consent
    decision; a stored denial survives reload).
  - Record per-journey UX and aesthetics scores (1–5) and typed, severity-rated
    issues (Functional/Usability/Visual/Content, P0–P3), triaged into follow-ups
    or explicit acceptances.
- Risks:
  - UAT observes a live public site: the sweep is read-only and
    privacy-preserving — the consent banner is declined, commerce stops at the
    honest-mock boundary, and no real credentials exist to enter.
  - Client-side state (cart, build, session) lives in browser localStorage and is
    isolated to the disposable UAT browser profile.
  - This slice changes no application code; defects become follow-up slices, so a
    poor score cannot silently turn into a drive-by production change.

## Steps
1. Write a reproducible Playwright driver (committed with the proof) that walks
   the journey list against `https://www.finspeed.online`, capturing screenshots,
   console errors, and per-journey observations into a results JSON.
2. Run the sweep at desktop (1440x900) and mobile (390x844) in light and dark
   themes; decline consent and verify the fail-closed behaviour and stored-denial
   reload; exercise the distributor gate by direct URL.
3. Visually inspect the key captures, assign UX/aesthetics scores per the quality
   model, and classify every issue found.
4. Triage findings into follow-up slices or explicit acceptances; write the proof
   README and design-qa addendum; close through the guarded commit flow.
