# Plan — WEB-030

- Context:
  The storefront supports light and dark themes, but the homepage always renders the dark Quiet Summit hero and dark terrain panels. In light mode the white surface, daylight content sections, and theme control therefore lead into night-oriented artwork with a heavy shade layer instead of a purpose-built light campaign.
- Goals:
  - Generate a cohesive light-theme desktop/mobile homepage hero with bright natural lighting, legible text-safe space, and no baked text or UI.
  - Generate matching Mountain, City, and Hybrid category panels with distinct terrain cues and consistent daylight treatment.
  - Select responsive light or dark assets from the live theme without duplicating homepage structure or breaking navigation.
  - Verify the result at desktop and mobile sizes in both themes.
- Risks:
  - Light photography can reduce white-copy contrast unless the left text-safe region and overlay are designed together.
  - Theme state is applied at runtime, so image selection must avoid a persistent wrong-theme source after toggling.
  - Generated category imagery must remain visually distinct at the shallow terrain-strip crop.

## Steps
1. Capture the current light-theme failure and measure the desktop/mobile hero and terrain crops.
2. Generate, inspect, and select dedicated light desktop/mobile hero and three category assets.
3. Add theme-aware responsive image selection and light-specific overlay/color treatment.
4. Add regression coverage for asset selection and run local lint, build, browser, accessibility, interaction, and console checks.
5. Capture visual proof, refresh telemetry, commit the governed slice, and record the production status without deploying unless separately authorized.
