# Plan — WEB-029

- Context:
  The shared storefront header now keeps stable geometry, but it still changes from a dark brand surface on Home to a light surface on catalog and product routes. The user wants the header to feel like one persistent application frame, so the Home treatment becomes the visual source of truth everywhere.
  During pre-release review, the user also identified that the raster logo and adjacent wordmark were numerically centered but not optically centered. Pixel-bound measurement confirmed a 3.5 px desktop visible-center mismatch caused by the source artwork's lower visual weight and the font line box.
- Goals:
  - Use one dark surface, light logo, light navigation, and light action treatment across all routes rendered by the storefront Header component.
  - Preserve the WEB-028 geometry contract and all existing interactions.
  - Align the painted logo and wordmark centers without changing the shared header height, brand scale, or mobile lockup.
  - Verify identical visual treatment and layout at desktop and mobile breakpoints.
  - Release through the existing AWS Amplify production application.
- Risks:
  - Route-dependent inline styles and responsive selectors can leave a hidden light-state exception.
  - Removing the light variant must not alter sticky positioning, focus states, or button handlers.
  - A shared color change affects catalog, product, cart, checkout, and service states and requires route coverage.

## Steps
1. Capture the released Home header as the dark visual source and inspect the existing light Shop state.
2. Replace route-dependent Header colors and assets with one dark shared treatment, then remove obsolete light-only responsive rules.
3. Add an automated visual-token contract alongside the existing geometry and navigation regression coverage.
4. Capture and compare Home and Shop at matching desktop and mobile states; fix all P0-P2 findings.
5. Apply a measured desktop optical offset, keep the already-correct mobile treatment, and add a breakpoint regression guard.
6. Run repository gates, commit, push, verify the Amplify release and public domain, complete proof/telemetry, and park the slice.
