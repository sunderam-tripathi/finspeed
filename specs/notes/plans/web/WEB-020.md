# Plan — WEB-020

- Context:
  The marketing site is live on `https://www.finspeed.online`, but we need a structured production UAT pass to verify the most critical journeys (home navigation, dealer locator, and support hub) behave exactly as described in SCN-001, SCN-004, and SCN-008 handoff packs — functionally and from a UX/aesthetics perspective.
- Goals:
  - Exercise core flows in a headed browser (Playwright + manual) from a rider’s perspective and confirm they match the acceptance features.
  - Validate that users can understand the content, navigation, and actions without guidance, and that the interface feels on-brand, trustworthy, and visually consistent (per `specs/references/handoff/_shared/tests/uat-ux-aesthetics.md`).
  - Capture screenshots, logs, UX ratings, and GA4 DebugView evidence so release decisions are backed by artefacts, not memory.
  - Log any defects or UX gaps and spin follow-up slices where needed.
- Risks:
  - GA4 verification may be limited if production analytics credentials or DebugView access are constrained.
  - UAT runs directly against production; we must avoid destructive or spammy actions (e.g., repeated form submissions).

## UAT Scope (per handoff + UX model)
- SCN-001 Site shell:
  - Primary nav shows “Bicycles/Models/Brand” and “Find a Dealer”.
  - Dealer CTA works on desktop + mobile (hamburger menu).
  - Footer exposes WhatsApp + email contact links that open external apps.
  - UX focus: clarity of purpose, discoverability of “Find a Dealer”, language toggle behaviour, mobile navigation comfort.
- SCN-004 Dealer locator:
  - Search for postal `201306` within 20km returns dealer cards and a synchronized map.
  - Invalid PIN (`000000`) shows validation message and preserves inputs.
  - Service filter chips update list + map; directions icon opens Google Maps.
  - UX focus: form copy and validation, map/list coordination, empty/outage states, perceived performance.
- SCN-008 Support hub:
  - Support email copy (`support@finspeed.online`, “Replies within 6 hours”) is visible and mailto works.
  - WhatsApp CTA respects consent (no tracking before consent grant).
  - Outage simulation disables WhatsApp tile and surfaces outage banner.
  - UX focus: incident communication, channel discoverability, form clarity, reassurance in error/fallback states.

## Steps
1. **Checklist & script alignment** — Derive a concise UAT checklist from SCN-001, SCN-004, SCN-008 acceptance features and the UX model in `uat-ux-aesthetics.md`; align it with `scripts/uat/production-uat.mjs` so automated and manual flows share the same scenarios.
2. **Headed Playwright run** — Execute `xvfb-run -a node scripts/uat/production-uat.mjs` (or local headed run) against production, exercising home, dealers, and support flows; export screenshots + JSON summary under `specs/proofs/web/WEB-020/artefacts/`, and log a per-flow UX/aesthetics rating (1–5) based on the quality model.
3. **Manual UX sweep** — In a real browser, replay each scenario (desktop + mobile viewport) focusing on first-time visitor, navigation/orientation, mobile-only, and error/edge-case experiences; record notes and screenshots for any usability or visual issues.
4. **Analytics & consent checks** — In GA4 DebugView (or configured analytics console), trigger a small number of events (dealer search, directions click, support channel click) after consent and confirm no events fire when consent is declined; tag any defects as Functional/Usability/Visual/Content with P0–P3 severity.
5. **Aesthetics review & sign-off** — With product/brand owner, review key templates (home, dealers, support) against the aesthetics checklist; record verdicts (Pass / Needs minor tweaks / Needs major rework) and decide which items are pre-go-live vs post-go-live.
6. **Proof & follow-ups** — Summarize results in `specs/proofs/web/WEB-020/README.md`, attach artefacts, mark RESULT (pass/fail), and create/flag follow-up slices for any issues that must be fixed before launch.
