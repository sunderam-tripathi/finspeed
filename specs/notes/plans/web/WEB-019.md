# Plan — WEB-019

- Context:
  Marketing site currently only renders the neo-noir dark aesthetic; we need a light counterpart so every page/component can switch palettes while honoring the same typography, gradients, and bilingual guidance.
- Goals:
  - Introduce theme tokens (light/dark) in `apps/web/src/app/globals.css` and propagate them through shared components (navigation, hero, cards, dealer locator, blog, support, brand story, testimonials).
  - Add a persistent theme toggle (auto respects system preference) and ensure persisted choice.
  - Validate via lint + Playwright (including axe) in both themes; capture parity artefacts/screenshots for each key page.
- Risks:
  - Token drift between themes causing inconsistent contrast or gradients.
  - Playwright tests may need updates to handle new toggle/state.

## Steps
1. **Token architecture** — Extend global CSS variables to define light-surface colors, neutrals, and gradients; audit components for hard-coded dark colors and replace with semantic tokens.
2. **Component updates** — Update shared layout (header/footer, locale switch, buttons, cards, consent banner, dealer locator modules, blog/support/testimonials) to conditionally consume light/dark tokens and ensure contrast meets WCAG.
3. **Theme toggle & persistence** — Implement hook/context for theme state (default system preference, allow manual toggle, persist to localStorage) and wire into header + global layout.
4. **Testing & proof** — Update Playwright suites to exercise both themes, run lint/tests, capture parity screenshots/logs, and document results in proof README.
