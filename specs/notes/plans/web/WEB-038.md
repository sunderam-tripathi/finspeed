# Plan — WEB-038

- Context:
  WEB-037 recorded ISS-1 (P1: `/dealers` "serves the editorial Visit page; the
  tested dealer locator is unreachable in production") and ISS-2 (P2: identical
  ~175-visible-char client shell and one generic title on every route), with a
  suspected WEB-022-era Amplify SPA-fallback rewrite as root cause. Fresh
  server-delivery evidence gathered on 2026-07-26 corrects that diagnosis:
  - Per-path routing does reach Next in production. The served `/dealers` HTML
    carries the `dealers` route segment in its RSC payload, `/definitely-not-a-route`
    uniquely carries the `designPath` catch-all marker, and byte sizes differ per
    route — impossible if a CDN rewrite served one shell for all paths.
  - The live `/dealers` page IS the tested locator (search field, service
    filters, map pins, two dealer cards, `/api/dealers` refresh) — verified in a
    real browser against production. WEB-037's scripted check failed only
    because the redesigned locator copy never contains the literal marker word
    "dealer", and the screenshot review misread the locator's "Visit Finspeed /
    Meet the bikes in Greater Noida." hero as the `Stores` editorial page (whose
    hero is "Meet the bikes in person.").
  - The real defect behind ISS-2 is in the app, not the delivery layer: every
    route in `apps/web/src/app` mounts the client-only `DesignApp`
    (`dynamic(..., { ssr: false })`), and the root layout holds the app's only
    `metadata` export. So every route legitimately SSRs a near-empty shell with
    one generic title, unknown paths return 200 through `[...designPath]`, and
    per-route titles exist only client-side (`StorefrontApp` sets
    `document.title` from `routeTitleLabels` after hydration).
  This slice fixes what is actually broken: server-delivered per-route titles
  and descriptions, honest 404 semantics, and deliberate storefront
  discoverability of the locator — plus a confirmatory, documented audit of the
  Amplify rewrite rules once AWS credentials are refreshed.
- Goals:
  - Introduce one shared route-metadata map consumed by both the design app
    (client `document.title`) and the Next route pages (server `metadata`), so
    titles cannot drift between the two layers.
  - Export route-specific metadata for every static Next route (home keeps the
    indexed brand title "Finspeed — Ride Beyond Boundaries"; the client home
    label aligns to it, removing the post-hydration title flip).
  - Upgrade `[...designPath]` with `generateMetadata` for known design routes —
    including real product names for `/products/<id>` — and `notFound()` for
    unknown paths so HTTP status agrees with the client router's NotFound view.
  - Link the locator deliberately: footer "Visit & Support" gains a "Dealer
    locator" item and the Stores page gains a CTA to `/dealers`; header
    "Visit Finspeed" keeps routing to the editorial `/stores` narrative.
  - Audit Amplify app `d2h8tz7elv2xy8` (ap-south-1) custom rules with the AWS
    CLI, record the JSON in the proof, and confirm no SPA-fallback rewrite is
    in effect (any harmful rule would be removed only with explicit steward
    approval).
  - Re-adjudicate WEB-037 ISS-1/ISS-2 in the proof with this evidence.
- Risks:
  - Changing served titles alters what crawlers index; mitigated by keeping the
    home title identical to the currently indexed brand title and deriving all
    other titles from the labels the client already displays.
  - Returning 404 for previously-200 unknown paths could break stale links; the
    known-route allow list is enumerated from the design router's own route
    table (storefront + distributor + products), so only genuinely unroutable
    paths 404 — the same paths that already render the client NotFound view.
  - The locator fetches `/api/dealers` at runtime; entry-point links do not
    change that contract. No dealer data or analytics behaviour changes.
  - Metadata edits touch every route page; the shared map keeps the change
    mechanical, and the full Playwright suite runs in the parity stack before
    release.

## Steps
1. Add the shared route-metadata module (route → path, title label,
   description) under `apps/web/src/design` as plain JS importable by both the
   design `.jsx` and the Next `.tsx` pages (`allowJs` is on); wire
   `StorefrontApp` to it and align the client home label to the brand title.
2. Export `metadata` from every static route page (`/`, `/blog`,
   `/brand-story`, `/catalog`, `/models`, `/support`, `/testimonials`,
   `/dealers`) via the shared map.
3. Rework `[...designPath]/page.tsx`: `generateMetadata` resolves known design
   routes (storefront routes, `/products/<id>` from the catalog data,
   `/distributor/*`) and unknown paths call `notFound()`; add a root
   `not-found.tsx` with its own title.
4. Add the locator entry points (footer "Dealer locator" item, Stores-page CTA
   to `/dealers`) and record the decision.
5. Add Playwright coverage that asserts server-delivered titles (JS disabled or
   raw HTML request) for a sample of routes, product-title resolution, and 404
   for unknown paths; run the full web suite plus unit tests in the parity
   stack.
6. After AWS reauthentication (`aws sso login`, steward-run): capture
   `aws amplify get-app` / `get-branch` rule JSON into the proof; confirm no
   SPA-fallback rewrite (or seek approval before touching any rule found).
7. Release through the guarded flow (merge = deploy), then verify against
   production: per-route titles in raw HTML, unknown-path 404, locator at
   `/dealers`, and re-run the corrected UAT dealers check; assemble the proof
   bundle with parity + production evidence and the WEB-037 re-adjudication.
