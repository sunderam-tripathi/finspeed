# Plan — WEB-022

- Context:
  The approved storefront redesign was initially implemented as a standalone Vite application and deployed to a new AWS stack. The existing production application is an AWS Amplify Next.js application connected to this repository, with established storefront, admin, analytics, and API contracts. This slice integrates the redesign into the real storefront and corrects the deployment target.
- Goals:
  - Preserve the existing Next.js application boundary and production integrations.
  - Implement the approved storefront visual language and shopping flows in `apps/web`.
  - Deploy the verified `main` release through the existing Amplify app in `ap-south-1`.
  - Verify `finspeed.online`, then remove the temporary CloudFront/S3 stack created during discovery.
- Risks:
  - Replacing the shell can regress existing bilingual, dealer, analytics, or content routes.
  - The current Amplify build configuration predates the repository's `apps/web` topology and may need a controlled update.
  - Production DNS and API endpoints are partially degraded; storefront release validation must distinguish pre-existing failures from redesign regressions.
  - Production environment variables include sensitive credentials and must never be copied into logs or source control.

## Steps
1. Inventory the current production app, repository topology, existing routes, and Amplify build contract.
2. Map the approved design implementation into the Next.js storefront while retaining compatibility routes and production environment contracts.
3. Run lint, build, browser-flow checks, and repository guard verification; capture proof artefacts.
4. Update the existing Amplify build target and deploy `main` through the connected application.
5. Verify the Amplify URL and `finspeed.online`, remove the temporary AWS stack, refresh telemetry, and close the slice.
